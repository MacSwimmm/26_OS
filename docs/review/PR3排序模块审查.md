额外需要修正的材料与边界问题：

- `explain` 没有校验策略名：`explain(U, N, "sjf")` 返回优先级理由，传 `runner_up=None` 时也直接返回末位说明，与文档“未知策略抛 ValueError”不一致。它也不校验两任务顺序，直接反向调用可输出数值不成立的“更高/更早”。应统一校验，并明确调用前提或拒绝反向输入。
- `docs/policies.md:57` 的 `argmin` 返回最小元素或最小元素集合，不能用来定义完整排列。完整序列应写为 `sort(C, key=k)`；若只表示队首选择，再用 `argmin`。
- C1/C2 混合多个到达时刻，却没有注明候选集观察时刻。这适用于“所有任务均已到达之后的一次纯排序”，不能解释为 t=0 就执行未来高优先级任务。纯排序函数不负责过滤未来任务。
- C3 没有让“同优先级、同截止时间、不同到达时间”成为独立决胜条件；该条件在单元测试中有覆盖，但手算交付材料仍应补齐。已有“输入顺序不变”测试只保存 ID，不能完整证明 Task 字段不被修改，应保存完整状态核对。
- C1/C2 把“整理茶歇台”设成 priority=2，而说明表给出的默认值是 1。自定义值本身允许，但应说明为排序实验特意配置，避免在答辩时误当默认业务定级。
