# 系统架构与算法说明

## 1 场景模型

茶歇服务员处理递送水杯、整理茶歇台、回收空杯和补充杯子四类任务。`Task` 是论文中的任务结构体：

\[
T_i=(p_i,d_i,e_i,Pre_i,R_i,preemptible_i)
\]

其中 `p` 是优先级，`d` 是截止时间，`e` 是执行时长，`Pre` 是前置任务集合，`R` 是资源需求。茶歇台、取杯区、回收区和通道建模为互斥资源；资源容量大于 1 时可以表示多个并行位置。

## 2 调度流程

1. 静态模式按初始任务的优先级、截止时间、到达时间和编号固定初始顺序；新到任务按到达次序追加。动态模式在每个时间片按紧急标记、优先级、截止时间、到达时间和编号重排。
2. 任务可由多个 `TaskStage` 组成。每个阶段独立申请增量资源、执行并按声明释放资源；旧式单阶段 `Task.resources` 仍受支持。
3. 银行家检查使用任务最大资源声明和当前分配，在申请前试分配。资源已占用导致的等待与安全序列检查拒绝分别记数。
4. 抢占和可恢复中断保存阶段与剩余工作，释放互斥资源；资源恢复后重新申请，已完成工作不重复计算。

## 3 死锁三件套

- **避免**：`deadlock.py` 的 `request_is_safe` 先试分配，再调用银行家安全性算法；不安全请求只进入等待队列。
- **检测**：根据资源分配表和等待请求表建立等待图。若 DFS 找到环，则记录死锁次数。
- **破解**：从环中选择优先级最低且允许回滚的任务，按检查点恢复并释放占用；记录重做工作量和重试次数。达到重试上限时撤销任务；环内无可回滚任务时记录未解除状态。

典型环是：任务 A 占用茶歇台等待回收区，任务 B 占用回收区等待茶歇台。`python3 run_demo.py --scenario deadlock` 用真实的分阶段任务申请同一组资源，分别运行银行家避免、只检测和检测后回滚恢复，并输出任务结果与事件轨迹。

## 4 中断模型

`InterruptType` 分为紧急服务请求、环境扰动、故障和资源恢复。紧急请求按策略进入队列，并在资源冲突时尝试抢占低优先级任务；环境或故障事件暂停受影响的运行任务，保存剩余工作、释放资源并在指定时刻后恢复申请。每条中断和恢复动作都写入 `trace`，便于论文画时序图。
